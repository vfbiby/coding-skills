# mt-protocol-forensics：MT4/MT5 协议调试取证

官方客户端做得到、我们做不到（或做得不一样）时，把「协议真相」挖出来并坐实的纪律。产出是**坐实的协议语义**（哪个 cmd、什么参数、响应里哪个字段），不是修复——修复另开票。实战全记录：vfbiby/mtapi #94–#97（forming bar 取证，工具已入库 mtapi 仓 `forensics/`）。

## 第 0 步：先花半天自查，再谈协议

抓包是重活。先在反编译源码/自家实现里排除低级原因（#95 教训：先入为主地把账记给服务器，后来 #96 翻案）：

1. 响应解析有没有丢尾部/边界条件写反；
2. 请求参数怎么算的（时区、取整、off-by-one）；
3. 依赖的「官方也这样」的假设是谁告诉你的——**没有 wire 证据的协议断言一律视为待验证**。

## 装备（全部现成，先复用再新写）

- **透传 relay**：mtapi 仓 `forensics/experiment-97/relay97.py`——本地监听、双向字节落盘、转发真服务器。**登录交换包必须脱敏**（MT4 wire 密码可离线还原）。
- **裸连接探针 harness**：`forensics/experiment-94..97/` 各 Program.cs。**必须裸连接收发**（不走 QuoteClient 事件解析——未知 cmd 会让解析器 throw 断线）。
- **离线解码器**：`forensics/experiment-97/decode97.py`——反射快照会话 codec 状态，把 relay 录的密文离线解成明文。MT4/MT5 的 wire 编码是可逆混淆不是加密，拿到 codec 状态就能解。
- **demo 账号**：`~/codes/mtcopy-demo-accounts/`（mt4-demo-account 技能可申请新的）。**绝对禁 live**；同系列账号互为独立复核（#96 用 …456、#97 用 …455）。
- 服务器时间一律 `api.ServerTime`，别用本地钟。

## 协议速查（2026-10 实测，细节以 forensics/ 报告为准）

**MT4 HIST（cmd 0x9C）**：请求 25B = cmd(1) + flag(1) + symbol(12) + tf(4) + from(epoch 秒,4) + count(short,2)。响应 = 24B 头（symbol12+tf2+count4）+ count×28B bar（time4+O4+H4+L4+C4 相对点位+vol8）+ 独立全零 1970 哨兵包；大页按 512 bar 分片。
- **count≥1**：from = 排他上界，只回已收盘 bar，服务器主动跳过 forming。
- **count=0**：from = **包含下界**，从 from 直达当前 forming bar；`from=当前分钟开头` 即「只要当根」；`from=当日00:00` 即「当天全量含当根」。边界：from 分钟尚无 tick → 回退返回前一根；from=日界 00:00 首根多含前日 23:59（成因不明，消费侧过滤）。
- 参考 DLL（MT4ServerAPI.dll）公开 API 原生放行 count=0。

**MT5 历史（cmd 102 族）**：请求粒度只到「日」（位域日期，无时分秒），当天应答自带 forming bar（#94）；另有无语义坐实的 type 56 推送（小 uint32，与 bar 无关，勿再猜）。

**通用**：broker 钟 = 服务器时区（实测 +3）；报价 tick 无 OHLC（只有 bid/ask），「tick 拼当根 open」从根上不可靠。

## 调试流程（顺序执行，每步产出落盘）

1. **参数探边**（无抓包，半天）：对目标 cmd 做 from/count/flag 变体矩阵 + 邻近 cmd 码扫描（#96 扫 0x98–0x9F），跨 ≥3 个分钟边界、分钟中段采样，判定「服务器肯不肯给」。命中即扩展参数组合确认可复现。
2. **wire 录制**：官方客户端（桌面版优先）经 relay 登录复现行为，双向字节落盘。接入方式按客户端选：
   - **Wine/桌面版**：服务器栏直接填 `127.0.0.1:端口`，零配置直连 relay（首选）。
   - **手机端**：MT4 手机 App **没有服务器输入框**（DNS/hosts 路线死路）；要抓手机走代理类 App 转 SOCKS，或 WDA 自动化配合。动手前先确认手机端有需要的配置入口。
   - Mac 锁屏会杀死一切 GUI 自动化——动手前 caffeinate + 关自动锁屏。
3. **离线解码 + 对拍**：decode97.py 解密文，逐字节对照协议速查表；与既有语料（#95/#96 dumps）结构对拍，判定通道是「已知 cmd 未知参数」还是「全新 cmd」。
4. **最终坐实**：用**我们自己的客户端**照发同款请求——服务器照样吐数据才算坐实（#97 加测了参考 DLL 公开 API，把「mtapi 要不要改」一并回答）。
5. **落票**：报告 = 观测/推断分标 + 原始 dump（SHA-256）+ 证据边界（覆盖了什么券商/时段/品种，没覆盖什么如实写）；修复另开票。

## 纪律

- **观测与推断分开标注**；否定结论必须写证据边界，不许把「没测到」说成「不存在」（#95 的教训）。
- 一次只动一个变量；独立账号复核关键结论。
- 凭据零落盘：密码走 env，wire dump 剔除登录包。
- 不碰 live 账号、不停本地栈、不 push 不关票（配合 dispatch-acceptance 走派工验收）。
- 官方客户端的「它显然是 XX」解释不算证据——用户/直觉说它「应该在后台攒 tick」也可以是错的（#96 翻案始末）。
