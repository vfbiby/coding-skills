当用户要求在 Codex 中启动一个可能运行很久的外部命令，并在完成后通知主会话时，使用一个子 agent 负责整个生命周期。

## 执行规则

1. 子 agent 必须在前台启动目标命令，并等待命令真正退出。
2. 不要使用 `nohup`、`&`、`disown`、cron、定时器或循环轮询进程状态。
3. 先确认命令是可执行文件还是 shell 函数/别名。对依赖用户 shell 配置的命令（例如 `glmfclaude`），显式用对应 shell 加载定义后执行，例如 `zsh -lc 'source ~/.config/zsh/claude.zsh; glmfclaude ...'`；不要假定子 agent 会继承交互式 zsh 的函数。
4. 将完整 stdout 和 stderr 保存到明确的日志文件；以进程退出为完成信号。
5. 记录目标命令的真实退出码。使用管道时保留原命令退出码，不要把 `tee` 的退出码当成任务结果。
6. 命令退出后检查用户要求的产物、报告和变更；不要只根据最后一行输出判断成功。
7. 子 agent 完成后向主会话回报结构化结果：成功或失败、退出码、关键输出、日志路径、产物路径以及失败原因。

## 推荐任务提示

```text
在前台执行以下命令并等待它退出：<command>
不要使用后台运行、nohup、定时任务或轮询。
保存完整输出，记录真实退出码，并检查命令生成的产物。
完成后回报：状态、退出码、关键输出、日志路径、产物路径和失败原因。
```

## 边界

这个技能依赖 Codex 的子任务完成通知：子 agent 在等待命令时保持活动，命令退出后再回报。它不能让子 agent 结束后继续监控一个脱离的后台进程，也不能单独唤醒已经空闲的主会话；那种需求需要 App Server 或外部回调桥接。
