# Web 交互逆向实测

用 playwright-cli 对目标站点做第一手交互取证，产出**交互规则表**。方法优先级：实测 > hook 取证 > 读源码推断；每条结论标注三者之一。

## 开工

1. 登录与进页：用所有者给的凭据；强弹窗（地理位置/公众号/引导）绕过并记录；**绝不点会破坏用户数据的按钮**（重置进度、删除等）。
2. playwright 默认会话会被其它并行任务劫持——长实验用独立会话 `playwright-cli -s=<任务名>`，收尾 close。
3. 截图存专门目录，命名带前缀（如 `re2-`），不覆盖旧证据。

## 逐键实测

1. 一类交互一验证：真实按键（`press`；键名首字母大写——`Space`/`Enter`，小写 `space` 无效）→ 按键前后各做一次 `eval` 读 DOM 状态 + 截图，diff 即该键的行为。
2. 按键序列有状态依赖（跳格/提交/重输），脚本化时先设计好序列，别让重置类操作污染计数。
3. 视觉状态（颜色/抖动/揭示）读 class 与 computed style，不只看文本。

## hook 取证

目标动作触发**前**装钩子，用计数与参数代替人耳肉眼：

- 音效：包 `Audio.prototype.play` 或 `AudioContext.prototype.createOscillator`（读参数要在 `start()` 时，创建时读到的是默认值）
- 朗读：包 `speechSynthesis.speak`，记 `utt.text` 与 `lang`
- 网络：包 `fetch`/XHR 记请求体与响应形态（只记结构，不导出数据）
- 动效：包 `document.createElement` 计数 canvas，或替换库全局函数计数调用

注意：应用可能在加载时缓存原生引用，钩子要在页面加载后、动作前装；直接调一次钩子函数自证生效。

## 挖实现

- 字符入口：隐藏 1×1 `<input>`（移动端/输入法友好，首选方案）还是 contenteditable 还是纯全局 keydown——`eval` 查 `document.activeElement` 与元素属性。
- 功能键监听在 window 还是元素上；失焦时键位是否仍生效。
- 行为对不上时读打包 js：按关键词（函数名、颜色值、接口路径）grep chunk 反编译关键函数，作推断证据。

## 假阳性防线

- 「成功」用客观指标判定：progress/上报请求是否发出、canvas 是否创建、库表是否落行；**页面文本匹配会假阳性**（常驻按钮文字、提示文案都含关键词）。
- 与人（所有者）实测结论冲突时，人的观察优先，回头做分场景复现（一次只变一个变量），误测结论要在文档里划线作废并注明原因。

## 产出：交互规则表

写到研究笔记（放项目的 research/ 目录），结构：

1. 规则表：每个键/事件一行——条件 → 行为 → 视觉/听觉反馈 → 状态变化
2. 阈值类行为写成精确事件链（如「第 3 次错触发一次，4、5 不再触发」），不用模糊的「≥」
3. 每条标注证据来源（截图文件名 / eval 输出 / 实测按键序列）与 实测/推断
4. 修订处标日期，冲突写「原结论 X 修正为 Y」，不静默改写
5. 副作用如实记录（动了账号什么数据、改了什么设置）
