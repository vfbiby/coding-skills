# 沉淀：坑 / 决策 / 未决事项

用在两个时刻：**踩到的当场**（正常入口——沉淀不是归档时才做的事），以及**归档前的兜底检查**。

## 第 0 步：先把候选列出来，再让用户挑

**不要问「这轮要沉淀哪几类」**——那是让用户替你回忆这轮发生过什么。**你回忆，他挑。**

先自己把这一轮里够格的条目**逐条列出来**，每条写三样：

- **拟归哪一类**（坑 / 决策记录 / 未决事项）
- **一句话内容**
- **推荐理由**：为什么它够格。理由要落在下面第 1、2 步的判据上（「换个人来做一样会踩」
  「当时有真实备选」「现在定它等于把一次性判断固化成纪律」），不是「感觉挺重要」

然后用 AskUserQuestion 让用户多选要落哪几条（也允许一条都不选直接退出）。

**够不够格由判据定，选不选由用户定。** 你把不够格的也列上去，等于把筛选工作推给用户；
你替他把够格的砍掉，他根本不知道有过这条。

## 第 1 步：分类。这是最容易错的一步

三类的边界靠**这件事的时态**来分，不靠它有多重要：

| | 它在说什么 | 一句话判据 |
|---|---|---|
| **坑** | 一件**已经发生过**、还会再发生的错 | **换个人来做，一样会踩** |
| **决策记录** | 一件**已经定了**、当时有别的选项的事 | 日后会有人问「为什么这么做」 |
| **未决事项** | 一件**还没定**的事 | 现在定它会把一次性判断固化成纪律 |

最常见的两种错分：

- 把**决策**写成坑。判据是「当时有没有真实备选」——有备选、选了一个，那是决策；
  没有备选、只是做错了，才是坑。
- 把**还没定的事**写成决策记录。写下来会让后来的人以为定过了，而**「以为定过」比「知道
  没定」危险得多**——它不会引发任何提问。

## 第 2 步：各类的形态

具体落点（目录名、编号规则）看项目文档；下面是形态与判据，跨项目都成立。

### 坑

**一条一文件**，文件名带编号与 slug（如 `P-139-grep-hit-is-not-having-read-it.md`），
四段：**症状 / 根因 / 处置**，外加一个严重度标记。

- **症状**写成别人能认出来的样子——「你会看到什么」，不是「我做错了什么」。
- **根因**要说清它**为什么不会报错**。会报错的错不值得进坑库，编译器和测试会教你。
- **处置**给一条能执行的规矩，最好带判据（「判据：每条断言都要写得出『怎么核实的』
  那条命令——写不出就是没核实过」）。
- ⚠️ **准入判据：换一个不知情、但同样认真的人来做这件事，他会不会栽在同一处？**
  会 → 是坑，根因在**那个东西的形状**上（接口骗人、命令名与行为不符、失败不报错、
  文档与实现漂了），写下来才有复利。不会 → 那是个人失误，**不进坑库**——收进来只会稀释
  密度，让真正的条目开始被跳过。
- **判据是实测的那种最值钱**：附上「这条规矩是怎么被验出来的」，比如「同一份文件里带了
  那一列的三条全对，错的两条恰好都在没有那一列的散句里」。

⚠️ **写入权只归主模型。执行方（子代理）只报「候选坑」，不许自己往坑库里写。**
理由是坑库的价值密度——它是要被反复读的，掺进没被判定过的条目就会开始被跳过。

### 决策记录（ADR）

**三条判据必须同时成立**才写：

1. **难以回退**
2. **日后会有人问「为什么这么做」**
3. **当时有真实备选**

少任何一条都不写。缺第 3 条写出来的是流水账，缺第 1 条写出来的是笔记——两者都会稀释真正的
ADR，让人不再逐条读。

形态：**标题就是那句结论**（不是「关于 X 的决策」，而是「用自有协议客户端接数据，不用终端
集群」），正文说清为什么，末尾一节 **Consequences：这个决定的代价与退路**。
代价那一节不许留空——**没有代价的决定说明你没在决定**。

### 未决事项

**一个编号一个文件**，顶部四个字段：

```
**状态**：未决 / 已结案
**严重度**：（阻塞 / 可以边做边定 之类的分档）
**关联变更**：<change 名，或「无」>
**关联 Requirement**：<Requirement 名，或「无 + 为什么无」>
```

正文写清：**没定的是什么**（把可选项 (a)(b)(c) 列出来）、**每个选项的代价**、以及
**什么时候才该定它**（「第二个样本出现时再定。现在只有一个样本，照它定规矩等于把一次性
判断固化成纪律」）。

已结案的条目**留存根不删除**，写明**去向**（指向 ADR 编号、或合并进去的那个变更）。
删掉的话，「已消费所以删了」和「压根没人写」事后长得一模一样。

## 第 3 步：落盘后

- 编号**从目录枚举现有最大值 +1**，不要凭记忆续——手抄的编号会撞。
- 项目若有文档预算或结构类扫描器，落盘后跑一次（新增文件常常正是撑爆预算的那一下）。
- 报一行给用户：这轮落了哪几条、编号各是什么。
