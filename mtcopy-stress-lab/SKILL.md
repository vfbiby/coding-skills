# mtcopy demo 跟单实验

## 定位与边界

定位当前 mtcopy checkout，读取 `CLAUDE.md`。下列文档路径均相对该 checkout；若技能由符号链接安装，先解析技能目录真实路径。检查 `tools/broker-lab/stress/cli.py` 与所需文档存在。只有技能、没有工具时，按复现手册获取发布分支；以当前 CLI `--help`、配置和资产 manifest 为实际参数来源。

先确定本次任务与既有授权：只读分析、离线准备、在线建栈/交易、恢复或版本切换。授权可沿用会话中的明确指示；调用技能本身不授权开户、登录接管、发单、重启或对外发布。存在待查明边界时先完成独立的只读/离线工作，再问必要的问题。

当前用户要求保留栈时，保留进程、数据库、日志与原始样本，收尾后暂停本栈关系；`cold` 与 `switch` 会重启，应推迟或改用已获授权的独立环境。

## 在线准备

1. **账号归属。** 复用原角色；新栈重复登录相同账号可能影响旧会话，先确定协调方案，暂停跟单关系不等于释放会话。demo 证明必须对应当前真实账号和精确服务器。Live 服务器名不能单独判实盘，MT5 DemoCluster 也不能单独判 demo；按工具的验证结果与所有者明确确认处理。过期/身份不明账号在发单前解决。
2. **规模与目录。** 从实际配置计算源事件、每源跟随人数、每波持仓与总计划结局。#292 模板为 5 信号×20 跟单、100 关系；6850 是历史映射行数，重新读取当前每账号目录并核对实际数量。先核验各平台品种、描述与交易属性，再审核显式映射；少量代表品种必须被全部对应关系覆盖。
3. **验证门。** 固定实际运行二进制/依赖版本及哈希，核对保证金、手数、时段、会话健康、持仓基线和 magic 冲突。执行获授权的单关系参考及完整一波开平验证，要求所有预期跟单 placed 且收尾；验证笔数另计。达标后才开始压力计划。

需补申请时读取可用的 `mt4-demo-account` 技能；按用户授权和已验证服务器有界执行，余额配置优先采用本次要求。成功后先私有保存凭据再验证；余额实际到账和账号数量由证据确认。复用资产不能增加旧账号余额。

## 运行与恢复

交替轮每次一个信号，等待其全部跟单收尾再轮换；并发轮每波五线程发起五信号，记录实际发起间隔，等待全部跟单收尾再下一波。持续默认在途一波，是闭环压力；只有显式配置到达间隔/在途上限的流水场景才能调查积压，均受持仓上限约束。

发现外部活动、断线或未决动作，先停发新信号并暂停本栈关系，再从字据核对持仓。只处理有源请求证据，或实验关系 magic、intent 与权威票一致的本次订单；Unknown/超时先核验原请求，不另发替代逻辑单。

恢复前保留原始结果、报告、计时和清单。按工具 `recover` 核验平仓及终局：物理残仓为零不等于 pending 已收敛；`clean` 不等于 `baseline_restored`。仅当检查点与 manifest 的 wave ID 逐条有序一致、全部收尾且原计划还有剩余时，使用相同参数 `--resume`。记录错位或无法核验时保留现场，不修改数据库结局制造恢复。计划完成时不补发重复波次。

若 pending 日志显示恢复已接手却长期未收敛，保存意图/时间线/会话证据，检查原生恢复入口。#292 曾通过 demo 会话重建触发恢复，但这属于另行判断的账号操作，不是每次超时的固定步骤，也不是重启核心服务的理由。

## 比较与交付

以 t2→t4 为发出耗时，分开分析到达→决定与决定→发出；成交/回执延迟另计。缺章留空。统计所有预期结局、实际请求及重试；每源事件/整波最慢跟单是独立统计单位，相关跟单不能虚增样本。短样本不宣称可靠 P95。

同场景、同账号/拓扑/映射/品种/手数、同初始历史规模与暖机，固定原版/候选哈希做至少两轮 ABBA；探针条件一致，最终无探针复测。失败、恢复、干扰、缺章和重试按比较门判定；只有可比数据才支持改善结论。分段变慢只是调查入口，归因到数据库、队列或券商需进一步证据。

交付记录实际计划/结局/耗时、未决与残仓、服务是否保留、验证范围及未完成项。账号/确认材料/数据库归档以加密包保存，密钥仓库外交接；公开 Git/issue 只含脱敏报告、模板、映射和密文。只有获得发布授权才上传；此前授权仍适用。完整性校验、真实解密和离线配置成功只证明离线复现准备完成，在线重建与交易验收分别说明。
