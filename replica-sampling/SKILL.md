# replica-sampling —— 复刻网站前端的视觉采样

把「像不像」变成可验收数字：对一个目标网站（通常是竞品）做**数字母本采样**，产出几何区间表 + 设计 token + 截图证据库，供 1:1 复刻的实施票与验收脚本消费。与 `web-interaction-recon`（交互行为逆向）互补：那个采「怎么操作」，本技能采「长什么样、怎么伸缩」。

触发：要 1:1 复刻某网站页面前；要把「观感差异」变成验收数字时；竞品疑似改版需重新采基准时。

## 0. 授权与账号纪律（先于一切）

- 凭证放所有者指定的本机凭证文件（git 外），**交付物零泄漏**（收尾对全部产物 grep 凭证串）
- 单点登录副作用先告知所有者：一次登录采样完即走，绝不重登
- **只读采样**：不点重置、不调 delete、不进写路径、不发练习/心跳类写操作；关闭弹窗类交互除外
- 记录竞品前端版本号（bundle 路径实读）——它是改版检测锚与结论时效的标签
- 竞品是别人的生产站：限速、不爬批量、不压测

## 1. 视口采样矩阵（开工前填好这张表）

先记录本轮目标：忠实复刻，或用户已授权的体验优化。优化项单列「竞品行为→我方目标→验收条件」；其余部分仍按母本验收，避免把主动差异当偏差，也避免自行扩大优化范围。

用户截图含浏览器外框时，先区分外框、CSS 内容视口、DPR 与缩放。优先读取用户当前页面的实际视口；只能根据截图估算时标【推断】，用邻近尺寸覆盖不确定区间。

| 档位 | 采哪些分辨率 | 深度 | 合同类型 |
|---|---|---|---|
| 大屏档 | 1920×1080 + 更宽一点（2000/2560 任一） | 逐盒矩形 + 截图 | 行为合同：谁伸缩、谁贴边、增长率 |
| **主基准** | 竞品设计视口（先确认，勿臆断） | **全量四层**（几何/token/截图/交互态） | **逐像素合同 ±4px** |
| 小屏档 | 1366×900 + 紧贴内容下限一点 | 逐盒矩形 + 截图 + 压缩顺序（先压什么高度） | 行为合同：无横滚、压缩顺序 |
| 平板档 | 768 / 1024 | 布局形态 + 截图 | 断点合同：何时换移动形态 |
| 手机档 | 375×812 + 360×800 | 设备模拟全量四层（标 DPR） | 断点合同 |

三条铁律：

1. **宽高分别采**：读取 CSS 断点及 JS 缩放逻辑，记录容器尺寸和缩放约束；宽、高断点两侧分别验证，覆盖矮窗口。
2. **插值先验证**：区间两端及至少一个内部点实测一致后再插值；换行、`min/max/clamp` 或 JS 缩放出现非线性时补采。
3. **每档的「压缩顺序」是独立合同**：记录头栏、工具栏、内容、统计和操作栏的纵向空间预算，区分固定占用与可伸缩部分。忠实复刻时实测竞品的压缩顺序；授权优化时优先收缩图片与留白，保留可读文字和可操作控件，内容超出预算时明确换行或滚动策略。

矩阵同时覆盖会改变内容高度的状态，按页面选取 tab、显隐、无图、长文本和多行释义等代表样本；短词或单一数据通过，仅能证明该样本。无需穷举所有组合，但要记录未覆盖状态。

## 2. 采什么（五层，缺一不可）

- **几何**：关键元素 `getBoundingClientRect` 批量提取 → 区间表；**逐盒 dump 必须落盘**（只在会话里不落盘=下游盲区，已踩坑）
- **Token**：`getComputedStyle` + CSSOM 遍历 → 色板/字体栈/字号行距/间距/圆角/阴影/过渡 → 机读 JSON，**必须过严格 json 解析校验**（已踩坑：裸值 `400/700` 炸解析）
- **表面清单（Surface Inventory）**：枚举**每个视觉表面**（页面底/侧栏/顶栏/卡片/行/输入框/hover 态…）× 背景/边框/圆角，成「表面→色值→有无边框」对照表；**含浏览器默认外观伪元素**（`::-webkit-scrollbar` 滑块/轨道/宽度、`::selection`、`:focus-visible`、`::placeholder`——滚动条配色属此类，CSSOM dump 竞品规则 + `getComputedStyle(el, pseudo)` 可直读断言）。**暗色系产品的分层全靠背景微差+零边框，人眼对近似灰阶失明**——这张表必须机器对账：竞品值（采样）vs 我方值（computed 实测）逐行 diff，并进验收脚本做逐表面断言（token 改了≠表面吃到了，要断 computed 值而非源码值）。另对双方截图做**同坐标定点色值采样 diff**（20 个固定点比 RGB），替代肉眼
- **视觉证据**：逐块裁切 + 每视口全页截图；双方固定视口、DPR、内容及状态，生成并排图和关键区域放大图，由主代理亲自复核。
- **交互态**：hover/选中/弹窗打开/焦点的样式 diff + 截图；动效用连续帧或短视频覆盖开始、中间、结束、取消及快速连续操作。
- **完整状态流程**：涉及输入或提交时，采完「空输入→输入中→错误→重试→成功→下一项」的适用状态，逐状态记录元素出现、隐藏及布局变化，再冻结差异清单。
- **状态独立性**：区分临时查看、持续显隐、设置及模式切换的作用范围；操作前后同时核对相关控件、已有输入和进度，记录哪些状态改变、哪些保持。

## 3. 语义钉死（动态数据）

动态口径用页面 DOM、只读 API 与 bundle 三源对账。以可复现的页面行为为目标，追踪「动作→实际执行分支→显示组件」解释机制；相关函数存在不等于正在执行。标明【实测】/【代码确认】/【推断】；冲突先查清，修正旧结论时显式作废并说明理由。

先确认目标页面、内容与状态已进入：重定向首页、登录页或暂停遮罩不算目标状态采样。无法进入时记录阻碍，分别标出本轮在线实测、历史采样（含版本）及用户截图的依据与局限；旧数据不改标为当前实测。

## 4. 移动端（手机/平板档）

- playwright 设备模拟：`viewport`（CSS 像素）× `DPR`（截图标注）× `UserAgent` × 触控；DOM 提取照常
- 模拟与真机的差异必须标注：无 hover（全 tap 态）、软键盘遮挡（采不到，标【需真机复核】）、安全区裁切
- 口径：**布局样式信模拟，手感类真机复核**

## 5. 产出物（三件，全版本化入库）

- `metrics-<page>.md`：视口矩阵表 + 区间表（±Npx 合同，逐条目号）+ 交互态 + **冻结差异清单**（编号=实施票范围，冻结制：清零即完成，新差异进下轮）+ 证据边界节（覆盖/未覆盖分列）+ 副作用如实记录
- `tokens-<page>.json`：机读设计 token
- `assets-competitor-<page>/`：截图库（逐块 + 全页，文件名带视口）

## 6. 下游消费约定

- 区间表 → **验收脚本**（自动闸门；每条断言注释引用母本条目号；基准视口逐像素、其他视口行为断言）
- **需求覆盖表**：每条用户要求对应「触发动作｜前后状态｜证据｜验收断言及结果」；未覆盖项明确标为未验证，完成判定逐条看覆盖结果，测试总数只作补充。
- **可见性验收**：页面无滚动不等于内容完整。检查关键内容是否在容器内、区域是否重叠，以及图片、文字是否被裁切；用裁切或隐藏实现的无溢出不算通过。允许的裁切、滚动或隐藏应来自母本或用户授权的目标。
- **操作栏验收**（页面有操作栏时）：核对全部操作及快捷键提示，检查长键名、整项换行和容器边界；按钮实际可点击、与内容区不重叠。逐项可见，不能用容器矩形正常代替。
- **冻结前核对母本**：主代理并排复核，逐条确认依据；未验证的推断保留待确认，不写成排他性要求。冻结后本轮范围即清单，新增差异进下轮。
- **随票现采**：竞品会改版（版本号变了先重采基准），非基准视口与后续页面开工前再采，不一次采全存档；采样产物有勘误随验收回写母本

## 7. 红线（历次踩坑转化，违者返工）

1. ❌ 目测截图钉数值 → ✅ DOM 实测（目测值被真机全面推翻过）
2. ❌ 只采一个视口 → ✅ 五档矩阵 + 断点两侧采样（只签基准的欠账会在宽窄屏爆雷）
3. ❌ 产物不过机读校验 → ✅ JSON 可解析、区间表可执行
4. ❌ 非基准视口「随缘」→ ✅ 每档都有明确合同
5. ❌ 推断混进实测 → ✅ 全表标【实测】/【推断】+ 证据边界
6. ❌ dump 只留在会话里 → ✅ 逐盒数据落盘入库

## 8. 工具要点

复用采集器：见[用法与配置](references/tool.md)，执行 `scripts/sample.mjs`；输出逐帧数据、截图及并排对照页。判定用 `scripts/gate.mjs`：±Npx 几何、指定样式、文字坐标、数量与横向溢出，豁免须写理由。

- playwright 独立命名会话（`-s=<name>`），与验收方/其他 agent 的共享会话隔离；截图用绝对路径
- 批量提取用页面内 JS（`getBoundingClientRect`/`getComputedStyle`/CSSOM `document.styleSheets` 遍历含 `@media`），不逐个目测截图拼
- 移动档用设备模拟参数；注意 dpr 影响截图物理尺寸，标注 CSS 视口为准
- 浏览器窗口宽 ≠ CSS 视口宽（缩放/DPR），**一切矩形以页面内 JS 读数为准**
- 正式浏览器验收期间冻结源码；同一次运行的截图、逐盒数据和检查结果绑定同一提交、脏状态、视口及页面状态。改源码后重跑受影响场景并更新整组证据，避免混用不同轮次产物；变异在独立工作树运行，避免热更新污染结果。
