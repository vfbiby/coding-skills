# 用 dlaude* 派活

本机有**三个** shell 函数，都用 DeepSeek 端点驱动 claude，都便宜，适合派实现与审查：

| 命令 | 主模型 | 特点 |
|---|---|---|
| `dlaudef` | `deepseek-v4-flash[1m]` | 快，但想得少、做得糙 |
| `dlaudep` | `deepseek-v4-pro[1m]`（subagent / haiku 位仍是 flash） | 慢，但思考更多、做得更好 |
| `dlaudefv` | `deepseek-v4-flash-vision-exp[1m]` | Flash 的视觉版：能看图 |

⚠️ **这三个名字在 2026-08-22 改过一轮**（`dlaude` → `dlaudef`、`dlaudepro` → `dlaudep`、`dlaudev` → `dlaudefv`）。仓库文档或旧会话里出现老名字时，按这张表换算；老名字在当前 shell 里**不存在**，直接用会 `command not found`。

**选哪个，看这活的失败方式**：

- **`dlaudef`**——活是「照着说明写代码」。要做什么已经在任务书里写死了，agent 只需要照做：加一列、补一个字段、把既有模式再套一遍、写一批照着模板的测试。这类活做错了**当场就红**，快比好重要。
- **`dlaudep`**——活里有**需要它自己判断**的成分。要在几种写法里选一种、要想清楚边界条件、要设计断言而不只是抄断言、改动跨多个文件且彼此有牵连。这类活的失败是**静默的**：它交出一份能跑、测试也绿的东西，而错在你没想到要去查的地方。多花的时间买的正是这个。

### 价钱：Pro 是 Flash 的 **3 倍**，且**错峰半价**

单价来自真实账单（DeepSeek 用量导出 CSV 的 `price` 列，2026-08-27 核对），**CNY / 1M token**：

| | Flash 错峰 | Pro 错峰 | Flash 高峰※ | Pro 高峰 |
|---|---|---|---|---|
| 输入（缓存未命中） | ¥1.5 | ¥4.5 | ¥3.0※ | ¥9.0 |
| 输入（缓存命中） | ¥0.05 | ¥0.15 | ¥0.10※ | ¥0.30 |
| 输出 | ¥4.5 | ¥13.5 | ¥9.0※ | ¥27.0 |

**高峰时段（官网原文）：UTC 01:00–04:00 与 06:00–10:00，周一至周五。** 换成北京时间是
**工作日 09:00–12:00 与 14:00–18:00**——只有这 6 小时是全价，**其余全部半价，整个周末也是**。
所以「等非高峰再派」比想象中容易满足：夜里、清晨、傍晚、周末都已经是错峰，真正要避开的
只有工作日那两段。
※ 表里 Flash 的高峰档没在账单里观测到（该 key 的 flash 用量恰好都在错峰），按 Pro 的比例推的。
vision（`dlaudefv`）与 Flash 同价，图片按尺寸折成 input token 一起计费。

三条读法：

- **缓存命中比未命中便宜 30 倍**（不是 50 倍——旧版这张表是凭印象写的美元估值，2026-08-27 被账单推翻）。
- **输出是最贵的一项**：Pro 输出 ¥13.5，是它未命中输入的 3 倍、命中的 90 倍。
- **Pro 各项都正好是 Flash 的 3 倍。**

两个都**便宜到不该按价钱选**。一次典型派活几美分，而**你自己复核一轮要花掉的时间，比两者的差价贵几个数量级**。

所以判据仍然是上面那条——**看这活的失败方式**，不是看单价：

- 失败会**当场变红** → `dlaudef`。省下的钱是真的，风险是零。
- 失败是**静默的**（交出一份能跑、测试也绿、而错在你没想到要去查的地方）→ `dlaudep`。**省下的那 3 倍差价，抵不过一次「测试全绿但结论是错的」**。

⚠️ **缓存命中比未命中便宜 30 倍，而这件事有个反直觉的后果**：把一件活拆成很多次短派活，**每一次都在整份任务书上付缓存未命中的钱**。同样的内容，一次大派活比五次小派活便宜得多，也更少犯「上下文没接上」的错。**除非有真实的并行收益，否则合并派。**

拿不准就上 `dlaudep`——**返工一轮的成本远高于它慢的那点时间，更远高于那点差价**。

需要最精细判断的活（协议解码、并发正确性、金额计算）三个都不用，走默认模型的 Agent 工具。

### 什么时候用 `dlaudefv`

**做界面的活用它**（用户 2026-08-22 明确的用途）。观摩页的排布、控件、图表这类前端改动派出去时首选它——因为界面这件事的验收本身就是视觉的：截下来的页面与 `prototype/observer-page-v6.html`（**以仓库里最新那一版为准**，旧版落后于已拍板的决策）的排布对不对得上、标线画歪没有、相邻按钮粘不粘连。这类退化**不会有任何测试变红**（见 CLAUDE.md「前端改动一律先看原型」），文字描述也替代不了；能看图的 agent 才可能自己发现。

派它做界面时，任务书里要**明确给出图的来源**——原型 HTML 的路径、以及让它自己用仓库的 Playwright 截图再看（`src/web-ui/e2e/`），否则它不会主动去找图，视觉能力等于白给。

边界：它是 Flash 的视觉版，**推理能力不比 Flash 强，别拿它当 `dlaudep` 的替代**。界面活里若含需要判断的成分（状态模型怎么设计、边界条件），那部分仍该 `dlaudep` 或主会话来定。

模型名带 `-exp`，是实验版本；**探活尤其不能省**，它比另外两个更可能整体不可用。

下文所有命令示例写的都是 `dlaudef`，换成 `dlaudep` / `dlaudefv` 时**其余参数一个字不用改**。

## 派活之前：留基线，并想一遍这活该不该派

**派活前先留一个可回退的基线。** 两条，按情况用：

- **已经成型的部分正常提交掉**（一次提交一件事，提交信息说清为什么）。这是最好的基线，顺带把
  历史理清。
- **未跟踪的新目录 git 帮不上忙** —— `cp -r <目录> <scratchpad>/baseline-<名字>/`。一条命令，
  不污染历史。

为什么这是硬要求：**没有基线，「把它改回去」就变成了「重新写一遍」，于是你会再派一轮。**
2026-08-27 实测代价：两轮纯撤回（撤掉一个写错的前提、还原六个被假红改坏的字符串），
净产出为零，吃掉当次派活总输入成本的一大半，每轮还要等 9–14 分钟。**其中一轮的全部内容
是把六个字符串替换回原值——`sed` 一条命令的事。**

**撤回、还原、机械替换：自己做，不派。** 判据不是**体量**（「四个文件里的四段」听起来不小，
但仍然没有任何判断成分），而是这两条：

1. **这活要不要做判断？** 要撤回的内容是已知的、要还原成什么是已知的 → 不派。
2. **手上有没有基线？** 有 → `git checkout` / `cp` 回来，几秒钟。

只有当撤回**同时伴随新的撰写**（撤掉一段错的论述、还要补一段新的取舍说明）**且撰写分量确实大**
时才考虑派活；即便如此，也先把纯机械的那部分自己做完，再派剩下的。

**同族的一条：让别人跑一趟之前，先问这一趟能不能不跑。** 转发闸门/工具的报错给执行侧之前，
**凡是报「某某不存在 / 找不到」的，先自己核一次**——存在性是双方都能独立核实的事实，一条
精确匹配几秒钟。实测反例：一次转发了 6 条「点名的测试不存在」，逐条回源后 **6 条全部真实存在**
（是那个闸门自己有盲区），执行侧照着错误报错把一份正确的计划改弱了整整一轮。

**每轮派完想知道花了多少**：`python3 ~/.claude/skills/dispatch-dlaude/dispatch-cost.py <scratchpad 目录>`
（加 `--flash` 按 Flash 单价折算）。它扫该目录下的 `*.log`，出每轮的 turns、耗时与三类 token，
并把「还在跑或被杀」的轮次单独标出来——**没有 `result` 行不等于消耗为零**。
⚠️ 它折算用的单价未经账单核对，只能当量级看（判据与未定项见该脚本文件头）。

## 步骤

### 1　探活

```bash
zsh -c "source ~/.zshrc >/dev/null 2>&1; dlaudef -p 'reply with exactly: OK'"
```

**探你这次真要用的那个。** 三个走同一个端点，但通道坏起来不保证同时坏（模型各不相同，`dlaudefv` 还是实验版）——探 `dlaudef` 通过，不构成 `dlaudep` / `dlaudefv` 可用的证据。

通道会整体坏掉（TLS 握手失败等），而**坏掉时 `RESULT` 仍报 `success turns=1 cost=0`**——判据是响应正文，不是 `subtype`。探不通就自己写，活照样干得完，只是慢。

### 2　写任务书

写到 scratchpad 的 `task.md`，不进仓库。内容见下面「任务书」一节。

### 3　发出去

```bash
S=<scratchpad 目录>
zsh -c "source ~/.zshrc >/dev/null 2>&1; dlaudef -p \"\$(cat $S/task.md)\" \
  -n '<活名：如 loginwindow-实现豁免>' \
  --output-format stream-json --verbose --permission-mode acceptEdits \
  --allowedTools '<按活收紧，见下>'" 2>&1 \
  | tee "$S/task.log" \
  | grep --line-buffered '^{' | jq -rc --unbuffered 'if .type=="assistant" then (.message.content[]? | if .type=="text" then "TXT "+(.text|.[0:220]) elif .type=="tool_use" then "USE "+.name+" "+((.input.file_path // .input.pattern // .input.command // "")|tostring|.[0:110]) else empty end) elif .type=="result" then "RESULT "+(.subtype//"")+" turns="+((.num_turns//0)|tostring) else empty end'
```

配 `run_in_background: true`。

这条命令的每一段都在挡一个具体的失败：

| 段 | 挡什么 |
|---|---|
| `--output-format stream-json --verbose` | `claude -p` 默认缓冲，跑完才一次性吐。加了它还能在中途杀掉进程后从日志里捞回已完成的调查 |
| `tee` **分流** | stdout 重定向到自己的日志文件会让 harness 的任务输出为空，UI 里点开什么都看不到 |
| `jq` **投影** | 原始 NDJSON 一条几千 token。投影把每条压成一行、正文截到 220 字、工具调用截到 110 字 |
| `--permission-mode acceptEdits` | `--dangerously-skip-permissions` 会被 auto 模式的分类器拦下 |
| `-n '<活名>'` | 命令行版 `/rename`，落成会话 JSONL 首行的 `custom-title`（2026-08-19 实测 `-p` 下可用）。不命名，会话在 `/resume` 里就是一串 UUID，事后没人知道哪个会话干过什么 |

**用 `acceptEdits`，不用 `plan`**：headless 下 `ExitPlanMode` 没有出口，审查 agent 以为自己交付了，整份报告消失。

### 4　等通知

后台任务跑完会自动叫你。这段时间去干别的。

**要看进度就 `tail` 那个 output 文件**（它已经是投影过的可读行）。用 Agent 工具派的子 agent 则不同——它的 output 文件是完整 JSONL 转录，读它会撑爆上下文，那种只能等通知。

**不要挂 Monitor**：它每条事件一次全量 API 调用。

### 5　自己复核

**跑一遍它说跑通的东西。** 报告说测试全绿，你自己跑；报告说注入实验红在第 N 条断言，你换一种注入自己验一遍。

判据：**你亲手跑出来的输出**与报告一致，且关键断言在你自己的注入下红在预期那条上。只读报告不算复核。

**被杀的 agent 会把注入留在工作树里。** 注入实验是「改坏 → 跑 → 改回来」，中途被杀就停在「改坏」那一步——工作树里那处**故意的破坏看起来和一处实现一样**，日志里最后一句还可能是「红了恰好一条」，读着像做完了。

所以**没有报告 = 先当作有半截注入没回滚**：`git diff` 逐处过一遍，找那种「删掉一个调用」「把 true 改成 false」的孤立改动，对着任务书里列的注入靶子核。已经发生过一次，恢复的是一处 `RevokeLink` 调用——**没有它，停用链接对正在看的观众完全不生效，而数据照常正确**。

顺带：这也是为什么**报告要写在测试跑绿之后、收尾之前**。收尾（回滚注入）没做完还有 `git diff` 兜底；报告没写，你连该去核什么都不知道。

**收 agent 的活时不要 `git add -A`。** 另一个 agent 可能正跑着，或刚落地还没复核——`git add -A` 会把它的改动一起卷进你这次提交，一个提交两件事，事后要 `reset --soft` 拆。2026-08-15 发生过一次。**按路径 add**，或者先 `git status` 看清楚这次到底该收哪些文件。

## 续派：复用上一个会话的上下文

新活跟上一次派活**强相关**时（同一模块的后续改动、对同一份审查报告的追问），可以不付冷启动，直接续上那个会话（2026-08-19 实测可用）：

```bash
# 发出去之后，从原始日志落盘 session id（投影流里没有它，要从 task.log 抓）
grep -o '"session_id":"[^"]*"' $S/task.log | head -1 | cut -d'"' -f4 > $S/session.id

# 续派：命令与「发出去」那条完全一样，只多一个 --resume
zsh -c "source ~/.zshrc >/dev/null 2>&1; dlaudef -p \"\$(cat $S/task2.md)\" \
  --resume \$(cat $S/session.id) \
  --output-format stream-json --verbose --permission-mode acceptEdits \
  --allowedTools '<同前>'" 2>&1 | tee "$S/task2.log" | <同前 jq 投影>
```

判据与边界：

- **必须显式 `--resume <id>`，禁用 `--continue`。** 所有派活的会话都挤在同一个 `~/.claude_deepseek` 项目目录下（按启动目录分桶），`--continue` 抓「最近一个会话」——那很可能是另一件活的。session id 要当轮落盘，会话文件有保留期，过些天可能已被清。
- **隔了几轮之后按活名找回会话 id**（`-n` 给的名字落在 JSONL 首行，grep 即得）：

  ```bash
  grep -l '"customTitle":"<活名>"' ~/.claude_deepseek/projects/*/*.jsonl
  ```

  活名建议 `<change 名或模块>-<动词短语>`（如 `loginwindow-实现豁免`）。**续派时同样给 `-n`，名字要重新归纳成整条 lineage 的意思**（如续了一轮审查修复后改成 `loginwindow-豁免+审查修复`）——会话里现在装的是两件事，名字只写新任务会把前一半的标签丢掉。实测 resume 时的 `-n` 是**追加**一条 `custom-title` 而旧名不动，所以按历史任何一期的名字 grep 都还能找到这条会话，改名不断链。
- **「强相关」才续，别把「同一个仓库」当理由。** 续派会把上一份完整转录（它读过的文件、跑过的命令输出）整个重放成输入。付两样东西：**上下文越重模型想得越歪**（旧会话里读过的代码还可能已被别人改了），以及下面这笔常被忽略的钱。
- ⚠️ **「缓存命中便宜 30 倍」只在缓存还热的时候成立，而两轮之间隔着人类决策时它必然已经凉了。** 2026-08-27 实测：一轮续派只跑了 46 turns，未命中输入却是当次全部六轮里最高的 131 万 token——比跑了 125 turns 的首轮还高一倍。因为中间隔了十几分钟（我读报告、用户做决定），**整份转录按未命中价重算了一遍**。
  判据：**同一轮里紧接着追问**（agent 刚交活、你立刻追一个问题）缓存是热的，续派真的便宜；**隔了一轮人类决策再续，成本约等于把整份转录当新输入重发一次**，此时冷启动一个新 agent + 一份紧凑任务书**又快又便宜**，且上下文干净。续派省的只是几百字的重新交代。
- **新鲜度按时钟判是错的，按「接触面之后有没有提交」判。** 会话里的内容分两类：**事实**（它读过的代码长什么样）过期最快；**过程**（debug 到哪了、为什么否了那个写法）不过期——续派要搬的只是后者。风险在于：冷启动的 agent 会重读文件，续上的 agent「记得」文件，而记忆是旧的、还说得很自信。查法（接触面在投影日志里都有）：

  ```bash
  ls -la ~/.claude_deepseek/projects/<桶>/<id>.jsonl        # 会话日期 = mtime
  grep -E '^USE (Read|Edit)' $S/task.log | cut -d' ' -f3- | sort -u   # 它碰过哪些文件
  git log --oneline --since=<那天> -- <上面的文件列表>               # 之后有没有被改
  ```

  三档：**0 提交**放心续；**有提交但与下一件活无交集**可续、任务书点名「这些文件已变，先重读」；**改的正是下一件活要动的东西**冷启动更省——续派省的交代成本，抵不过纠正它过期印象所费的笔墨。先看旧会话的 `report-<活名>.md` 还在不在：**旧会话的价值本该早就蒸馏进报告**，够用的话连 resume 都不需要，新任务书里引它即可——resume 搬的是「报告写不下的工作记忆」，不是事实。
- **续派不豁免任务书规矩。** 该点名的文件照样点名（写「先重读 X，代码可能已变」），该划死的范围照样划死——旧会话只知道旧任务书，新边界它不知道。
- 续上的会话沿用同一个 scratchpad 目录（`task.log` / `task2.log` / 报告都在一起），收活时一眼看全。

## 白名单

`--allowedTools` 必须写在命令行上。**`.claude/settings.json` 的 `permissions.allow` 对派出去的 agent 无效**（workspace 未 trust）。

**用下面三个具名 bundle，整块粘贴，不要每次手拼。** 手拼的失败方式是**想不全**：2026-08-27
一次派活给了 `Read,Write,Edit,Glob,Grep,Bash(openspec:*)`，agent 想用 `sed -n` 与 `ls` 看文件，
被拒 5 次才改用 `Read`/`Grep`——每次被拒多绕一个 turn，而每个 turn 都要重吃一遍上下文。
拒得准不是问题（前缀匹配对整条命令串生效，复合命令 `a; b` 也按整串判），给窄了才是。

```
# ① 只读调查（审查、排查、回源核对）——绝不给 Write/Edit

# ② 实现（写代码 + 自测）——在 ① 基础上加写与构建
```

三条：

- **给 `Grep` 工具，不给 `Bash(grep:*)`。** 后者能让 agent 去 grep shell snapshot，而 `dlaudef` / `dlaudep` / `dlaudefv` 的函数体都在里面，带着硬编码的 API token。
- **`Bash(xxx:*)` 是前缀匹配。** `set -a; . ./.env; set +a; dotnet test` 不以 `dotnet` 开头，会被拒。把 `source .env` 封进 scratchpad 里的一个脚本，白名单给 `Bash(bash:*)`，任务书里写死「跑测试只能用 `bash <脚本路径>`」。
  收太紧的代价不是报错而是误导：agent 看到的现象是「`PG_DSN` 是 unset」，于是反复 `printenv` 试探，最后得出「沙箱对凭据名做了静态保护」这个完全错误的结论，烧掉十几轮。
- **审查 agent 不给构建工具。** 两个 agent 同时构建会抢 `obj/` / `dist/`，两边都坏。任务书里写明「构建与测试由主会话跑」——它照样能读代码、回源核对、写报告，于是实现与审查可以真并行。

## 任务书

派出去的 agent 是**冷启动**的：它不知道这个仓库、不知道之前几轮做过什么、不会自己去找该读的文件。

- **点名要读哪几个文件**，用全路径。相关 ADR、坑库的具体条目（`docs/pitfalls/P-<编号>-<slug>.md`）、spec、tasks——不点名它就不读。
- **点名前先 grep。** 拿本次改动的领域词（表名、模块名、指标名）去文档目录搜一遍，命中的全部点名。凭回忆点名时，漏掉的那份往往正是最该读的那份——因为你记得住的都是你已经在想的。
- **写清楚这一轮最容易做错的地方是什么、错了会怎样。** 不是「实现 X」，是「X 做错不会报错，只会让 Y 看起来更好」。
- **报告写进文件，不要只留在流里。** 任务书里给一个绝对路径（scratchpad 下的 `report-<活名>.md`），要求它**边做边写、每完成一节就落一次盘**。

  流是易失的：agent 被杀时最后那条消息还没发出来，报告就彻底没了——**已经丢过两份**，其中一份定了一组参数（一致性校验的抽样比例与触发时刻），理由最后只能从它留在代码注释里的文字反推。而磁盘上的半份报告永远比零份强：它至少说明做到哪一步、下一个嫌疑是什么。上一次靠残留日志捞到「`ReadCoverageRows` 是好的，问题在循环内部」这一句，直接省掉了重查一遍。
- **报告写在测试跑绿之后、收尾之前。** 长任务接近上限时会被杀，活干完了报告丢了——发生过三次。任务书里写死这个顺序，代价为零。
- **要求每次调试/注入改动做完立刻改回来并重跑确认绿。** 有一次 agent 被杀在「把 catch 临时改成重抛」和「改回来」之间。那行 `throw;` 若跟着提交，异常就从「记一条告警、下轮重试」变成打断整个循环——**而那条路径没有任何测试覆盖**。
- **划死不许碰的东西**：别的模块、别的任务组、既有测试、文档目录。
- **注释只许引用能回源核对的出处**：ADR 编号、spec 的 Requirement 名、坑编号 `P-n`、文件全路径。任务书里的「第 3 组」「6.7」这类编号是一次性的，写进注释就是死链。
- **交付要求写成可检查的**：贴真实测试输出（条数）、贴注入实验的失败输出、逐条回答指定的问题。「写份报告」换来的是复述注释，「数出你写了几条断言」换来的是真数了。

## 被杀之后

`RESULT` 行缺失 = 被外部终止（不是崩溃，也不是通道坏——通道坏时 `RESULT` 仍会报 success）。**别急着重派，先读磁盘**：

1. `git status --short` —— 落了什么
2. 那份半成品报告 —— 做到哪一步、下一个嫌疑是什么
3. **`grep -rn "TEMP\|DEBUG" src`** —— 调试残留。这一步不是洁癖，理由见上面那条

判断要不要重派的判据：**残留的诊断线索够不够你自己收尾**。够就自己收——重派要付一次冷启动，而一条已经定位到函数级的 bug，自己修比重新交代便宜。

顺带：日志里分辨不出「被人停掉」和「被系统杀掉」。查后者看 `Console.app` 的 `jetsam` / `memorystatus`，或 `sysctl vm.swapusage`（swap 打满时 macOS 会杀大进程）。**分辨不出来就别下结论**，把它当成「随时可能发生」来设计任务书，比查明原因更有用。

## 通道坏了

探活不通、或 `RESULT` 报 success 但正文是错误——自己写。派活是省时间的手段，不是前提。
