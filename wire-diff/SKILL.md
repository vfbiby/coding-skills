# wire-diff：报文级差分取证

一个客户端实现踩坑、参考实现不踩，怀疑点从「应用逻辑」下沉到「线上报文」时的定位纪律。产出是一个坐实的毒包（哪条报文、两侧各是什么行为），不是修复——修复另起。

## 第 0 步：差分前置（没跑过就不许进入抓包）

把「服务端/环境侧行为」的归因压到差分实验之后：参考实现（闭源 DLL 也算）与移植实现，**virgin 环境、同序列，唯一变量 = 客户端实现**，各跑一遍目标行为。

- virgin = 全新账号/全新环境，与所有在跑实例零交集（会话接管、历史状态都会污染）。
- 完成判据：两侧行为**可复现地不同**（参考实现侧至少跑满一个完整观察窗仍无症状）。
- 参考实现也不踩 → 归因成立，收工；只有移植实现踩 → 进入第 1 步。

## 第 1 步：结构抓包代理

加密流比不了明文，比**结构序列**：报文个数、方向、字节长度、时序间隔。

写一个本地 TCP 代理（asyncio 约百行）：监听本地端口转发真实服务端，全双工逐包落盘（UTC 时间戳、方向、长度、首部 hex）。两侧客户端 host/port 指向代理；客户端若对 host 做校验导致登录失败，换代理形态并如实记录。

完成判据：两份结构序列文件落盘，每个包带时间戳/方向/长度。

## 第 2 步：双臂同序列过代理

移植实现与参考实现各走一遍**完全相同**的行为序列（镜像参考实现的调用序，含它「先做什么后做什么」的顺序——顺序本身就是被检变量）。

## 第 3 步：结构对齐

比对两臂序列，找**第一条结构性分歧**：多发的包、少发的包、长度异常、时序异常。

- 重点窗口：参考实现不踩坑的那个动作**前后**（登录完成到该动作之间尤甚）。
- 登录握手段两侧语义应相同，先对齐它可校准比对方法本身。

完成判据：指到第一条分歧包，双方序列中位置明确。

## 第 4 步：明文定位

分歧包回两侧源码定内容：

- 移植侧：读发送路径源码，确定该位置发出的命令与 payload 字段。
- 参考侧：读权威参考源码（反编译源也算），确定同位置发什么/不发什么。
- 每条结论都要 file:line，**亲读原文核实**，不许二手转引。

完成判据：能填进判定格式的两行「移植侧行为 / 参考侧行为」，各带源码出处。

## 第 5 步：毒包验证（坐实）

scratch 探针单变量验证：把可疑报文去掉或替换成参考侧形态，同序列下症状消失即坐实。消失不了，回到第 3 步——说明分歧点找早了。

## 判定格式

> 毒包 = <命令/报文名>；移植侧行为 = …；参考侧行为 = …；证据 = 抓包结构序列 + 两侧源码 file:line；验证 = 去包/换包后症状消失。

定位即停。修复是另一件事——带着坐实的毒包另起，不要在同一轮里既定位又修。

## 实战注记（2026-09-19 MT4 首战沉淀）

- **加密流先问「密钥可否复算」**：会话密钥若可由线上字节 + 共享秘密（口令/握手材料）复算，直接做**解密型 MITM**（代理解密再加密转发，或旁路复算比对），明文比对一步到位。结构比对只是解不出来时的第一刀。
- **解密正确性要对账**：派生结果与其中一侧行为 trace 逐字节对账一致后才可用，否则全盘皆错。
- **单字节毒包可用逐位 XOR 坐实**：怀疑「同一命令用错密钥流」时，密文差 = 明文差 ⊕ 密钥流差，逐位吻合即铁证。
- **小心「时机毒」表象**：同一字节序列换时序结果不同，真身往往是**状态分叉**（如克隆的编码器/上下文滞后于主线推进），时机只是暴露窗口。定位要落到「哪条报文在哪个状态下发出」，停在「什么时候发」会让修复碰运气。
- **fix 生效 ≠ 病根**：某次行为改动让症状消失，只说明它避开了触发窗口；回到本技能把真身挖出来（本案：订阅移前治了标，病根是编码器分叉）。
- **验证前先确认被测二进制包含被测修复**：重跑探针前强制重编（`touch` 依赖 crate 的 lib.rs 再 build），看编译输出里依赖 crate 是否真的重编——path 依赖的 mtime 缓存会骗过 cargo，拿着旧二进制验证新修复会把「修复有效」误判成「无效」。修复后验证出现矛盾结果，第一反应查二进制新旧，第二反应才查修复本身。
